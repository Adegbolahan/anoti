
# CEO Plan: Plugin-Native Workflow (project-scaffolder v3)

Generated by /plan-ceo-review on 2026-08-07

## Problem

`project-scaffolder` ships an enforced 5-phase development workflow with a commit
gate. The gate does not fire, the review command depends on four agents the plugin
does not ship, and four separate files disagree about what version is installed and
what commands exist. Zero tests, zero CI.

The root cause is architectural: **the plugin copies files into projects, and copies
drift**. That is why `/update` already carries two hand-written prose migrations that
an LLM must interpret, and why `marketplace.json` is stranded at 1.0.0 advertising
`/scaffold` and `/scaffold-minimal`, which have not existed for two releases.

## Vision

### 10x Check

The 10x version is not more phases. It is **the plugin proving its own gates fire, on
every push**. A workflow-enforcement plugin with zero enforcement of itself is asking
for trust it has not earned. A hook-simulation harness that feeds synthetic hook
payloads through every hook and asserts exit codes converts 3,524 lines of prose and
bash into a system with a contract.

### Platform Potential

With a clean state machine and a versioned gate contract, "workflow enforcement"
becomes infrastructure other plugins build on. A second plugin could add its own phase
or its own gate. That is why the state schema gets versioned now, while there is one
consumer, rather than later when there are five.

## Chosen Approach

**Approach C — Plugin-native workflow.** The workflow commands (`implement`, `review`),
the three skills, the hook suite, and the four review agents move _into_ the plugin as
plugin components. Scaffolding is reduced to what is genuinely project-specific:
`CLAUDE.md` and `.claude/project/`. `/update` collapses toward `/plugin update`.

Rejected alternatives:

- **A: Repair in place** (human ~1 day / CC ~30 min) — fixes today's six defects and
  leaves the drift engine that produces tomorrow's.
- **B: Deterministic scaffolder** (human ~3-4 days / CC ~1.5 hr) — script-driven copy
  and CI-asserted output tree, but still copies everything and still needs a written
  migration per release.

C was chosen because it eliminates a bug _class_. The `/update` migration prose and the
four disagreeing version numbers are the same disease; only C cures it.

**Key risk to retire first:** verify that plugin `hooks/hooks.json` supports every hook
event currently in use — `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`,
`Stop`. If any event is not plugin-providable, that portion of the hook suite stays in
scaffolded `settings.json` and C becomes a hybrid. This check sizes the entire job and
must run before any other work.

**Sequencing decision:** harness first, written against the _current_ hooks. This is the
only ordering where the harness verifies the fixes rather than agreeing with them after
the fact. Accepted cost: partial harness rewrite when hooks relocate into the plugin.

## Accepted Scope

- Verify plugin `hooks/hooks.json` event coverage (gates the whole plan)
- Hook-simulation harness + CI, written against current hooks, before the relocation
- Fix D1-D11
- Relocate `implement`, `review`, 3 skills, and the hook suite into the plugin
- Ship the 4 review agents inside the plugin
- Cap the auto-fix loop with an explicit cycle ceiling
- Scope-detected review tracks
- Detect-once formatting; typecheck on `Stop`
- Recorded one-shot override
- Phase bar + explanatory blocked-commit message
- `schemaVersion` with forward migration
- CI version-consistency check across `plugin.json`, `marketplace.json`, the
  `settings.json` template, and `CHANGELOG.md`
- Delete `template-customizer`, `.githooks/pre-push`, `scripts/bump-version.sh`, and
  the `/update` versioned prose migrations

## Deep-Review Decisions (Sections 1-11)

Eight findings surfaced during the 11-section review that were not on the cherry-pick
ballot. All eight were decided.

| #   | Finding                                                                                                                                                                                                                             | Decision                                             | Reasoning                                                                                                                                                                                    |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Every shadow path fails open.** Malformed payload, missing jq, corrupt state, and unknown phase all end in `exit 0`. A gate that fails open is not a gate.                                                                        | **Fail closed — block and explain**                  | Any state the gate cannot positively confirm as `review_passed` blocks, with a one-line reason and the exact recovery command. Accepted tension with commit `1456b67` ("reduce hook noise"). |
| 2   | **Hooks are unreadable and untestable.** The commit gate is one JSON string with a pipe, a command substitution, two nested `if`s, and a 3-branch `case`. The phase-read idiom is duplicated 4×, the story-read idiom 3×.           | **Refactor to thin delegates, before E1**            | `workflow-state.sh check-commit` / `on-edit <path>` / `on-prompt`. Load-bearing for E1: a 900-char JSON-embedded bash string is near-untestable; a named subcommand is a one-line test.      |
| 3   | **Shadowing copies strand every existing user.** A v2.1.0 project's `.claude/commands/implement.md` would shadow the plugin's fixed version, delivering none of the D1-D11 fixes while appearing to upgrade.                        | **Backup then delete, with printed manifest**        | Move copies to `.claude/.backup-v2/`, print what moved and how to restore. Backup is what keeps rollback from stranding users with zero commands. Requires a confirmation prompt.            |
| 4   | **Zero observability.** No logging, no metrics beyond `reviewCycle`, and `timestamps[phase]` is overwritten on re-entry so a second review cycle erases the first. "Why did this commit go through?" is unanswerable.               | **Append-only transition log**                       | One JSONL line per transition, gate decision, and override in `.claude/project/.workflow-log.jsonl`. Needs a `.gitignore` entry and eventual rotation.                                       |
| 5   | **A1 — state path breaks under relocation.** `SCRIPT_DIR=$(dirname "$0")` resolves to the shared plugin dir after the move, so every project on the machine would share one state file.                                             | **`$CLAUDE_PROJECT_DIR` with git-toplevel fallback** | Hard-error if neither resolves rather than guessing. The hard-error path gets its own test.                                                                                                  |
| 6   | **E-GAP1 — an empty review counts as a pass.** A track that returns nothing yields zero findings, Step 2 merges zero, Step 4 sets `review_passed`. A review that silently did not happen is indistinguishable from one that passed. | **Empty result is a failure**                        | Each track must return a structured verdict. Nothing/timeout/error marks the review INCOMPLETE, holds state at `under_review`, and names the failed track.                                   |
| 7   | **S-GAP1 — commit gate is anchored `^git commit`.** The safety blockers use unanchored grep; the gate does not. `cd frontend && git commit -m x` bypasses it. A second independent hole in the same gate as D1.                     | **Unanchored match, same as the safety blockers**    | Accepted cost: false positive when the literal text appears in an echo or commit body.                                                                                                       |
| 8   | **D-GAP1 — concurrent state writes race.** Every `advance` is read-modify-write; Claude issues parallel Edits, so two hooks can silently drop a transition.                                                                         | **Portable `mkdir`-based lock**                      | `mkdir` is atomic on every POSIX filesystem; `flock` is not in macOS base userland. Stale-lock timeout and its test are mandatory.                                                           |

### Folded into baseline without a separate decision

**S-GAP2 — secrets blocker gaps.** The blocker matches `.env*`, `credentials.json`,
`.pem`, `.key`, `.p12`, `.pfx`. Extend to add `.envrc`, `id_rsa` / `id_ed25519`
(no extension), `terraform.tfvars`, `*.jks`, `*.keystore`, `*.crt`, `.npmrc`,
`.pypirc`, and add a Bash-side check for `> .env`-style redirects. Keep the existing
`.env.example` / `.sample` / `.template` allowlist.

**D-GAP2 — `/update` version comparison.** Handles "same" and "older"; a project on a
_newer_ version than the plugin falls through silently. Add an explicit branch.

**D-GAP3 — stuck at `under_review`.** Interrupting the review loop blocks commits
permanently with no supported escape. Already solved by E2 (recorded override).

### Test coverage baseline

0 of 92 paths tested (80 code branches, 12 user flows). Mandatory regression tests
under the iron rule: D1 (gate unreachable at `plan_approved`), S-GAP1
(compound-command bypass), A2 (missing jq disables the gate). The load-bearing pair
is the gate blocking in a scaffolded repo and staying silent in an unscaffolded one.

### Architectural note

Deterministic command hooks everywhere a gate is involved, against the documented
default which recommends prompt hooks. Determinism is the product. Prompt hooks
appear exactly once, in skillify, where the question is a genuine judgment call.

## Phase B Engineering Review (2026-08-07)

Ran after Phase A shipped (commit b89565c, 72/72 green). Target: the remaining
v3.0.0 scope, centred on who owns the reviewer. 5 decisions, all resolved.

### The finding that reframes the product

**The gate does not constrain the entity it exists to constrain.** Demonstrated
on a real scaffold:

```
phase: implementation_in_progress
  git commit                                → exit 2   BLOCKED
  workflow-state.sh advance under_review    → allowed
  workflow-state.sh advance review_passed   → allowed
  git commit                                → exit 0   ALLOWED
```

`pre-bash.sh` gates `git commit` but not the transition that opens the gate, so
the agent under gate can unblock itself in two commands. It is written to the
audit log, but identically to a legitimate review pass, so the log cannot tell
a real review from the magic words.

The asymmetry: `override` is a recorded, deliberate, one-shot bypass. This is an
unlimited one sitting next to it, indistinguishable in the log.

There is no cryptographic answer. An agent with bash in the same filesystem can
forge anything checkable. The real choice is whether faking it stays trivial and
invisible, or becomes explicit and visible in the diff.

### The gate was already pluggable

`pre-bash.sh` reads a phase and nothing else. It cannot distinguish four
sub-agents from `/plan-eng-review` from a human. Pluggability was never a thing
to build; `/review` is simply what currently sets the phase. The open question
was only whether the plugin ships a default reviewer and writes the contract
down.

**[Layer 1]** This is GitHub branch protection with required status checks, and
the `pre-commit` framework: own the contract, ship a reference implementation,
let the ecosystem supply the rest.

### Decisions

| # | Finding | Confidence | Decision |
|---|---------|-----------|----------|
| 1 | `/review` dispatches 4 agent types the plugin does not ship, duplicating a deeper suite already in use | — | Ship the contract plus **one** dependency-free reference reviewer. Drop the 4 agents. |
| 2 | The gated agent opens its own gate in two commands | 10/10 | Require `--evidence` on `advance review_passed`, record path + hash, **and state plainly in the docs that this is a guardrail against drift, not an adversarial control**. |
| 3 | The commit regex is byte-identical in `pre-bash.sh:63` and `post-bash.sh:13` | 10/10 | Move `is_commit()` into `_common.sh`. Decision 7A accepted a known false positive, so this regex will be tuned. |
| 4 | The evidence check needs a newest-source-edit time that does not exist | 9/10 | `post-edit.sh` stamps `lastSourceEdit` into state, under the existing lock. |
| 5 | Skillify puts an LLM call on `Stop`, where the typecheck already runs | 8/10 | Fire only on the transition to `complete`, short timeout, approve on any failure. |

job." Only the version-consistency check was built. v2.2.0 has no tag to pin or
roll back to. Tracked as B8.

### Phase B shrank

Phase A. What remains: relocation, the `/update` migration, the reviewer
decision, skillify, the evidence requirement, and the release tag.
